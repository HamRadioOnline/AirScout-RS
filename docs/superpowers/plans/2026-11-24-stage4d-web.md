# Stage 4d — `as-web` Embedded HTTP Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stage 4d of the spec, "Integrations": the C# web server (`AirScout/Webserver.cs`) as the crate `as-web`, with the web UI assets embedded in the binary, every route and JSON shape of the C# server, the `planes.json` writer, start and restart in the Options cycle, and the HTTP port in the Options Network tab. The binding owner decisions D1-D4 of the survey apply, and the security holes of the C# server are closed.

**Architecture:**
- **`as-web`** (new crate, no domain dependencies) holds the protocol and the server: `json.rs` (Newtonsoft-compatible number and date text), `dto.rs` (the C# object shapes as serde structs), `query.rs` (C# query parsing), `route.rs` (the C# dispatch order), `assets.rs` (a fixed `include_bytes!` table) and `server.rs` (axum on its own std thread `web`, a current-thread tokio runtime and a blocking pool for the handlers).
- The handlers need the station, elevation and propagation data, so they are an `as_web::Api` trait. The `airscout` crate implements it in `web_api.rs`, `web_stations.rs` and `web_paths.rs` over the existing `Paths`, `PlaneInfoCache` and a live `Settings` snapshot.
- `web_service.rs` (airscout) owns the running `WebServer` and the `planes.json` writer thread.
- `RealServices::start_integrations` restarts the server when its address or activation changed (D3). `stop_integrations` leaves it running, as the C# stop list does.
- The app pushes a `Settings` clone at most once per second while the server is active. No request touches the UI thread.

**Tech Stack:** Rust 1.95+, std threads, serde/serde_json, chrono. New, pending the owner (Open questions): `axum` 0.8.9, and `tokio` 1.54.1 as a direct dependency (already in `Cargo.lock`). egui_kittest 0.37 and tempfile stay dev dependencies.

- Produces (`query.rs`):

  - `pub struct Query { pairs: Vec<(String, String)> }`:
    - `Query::from_raw_url(raw: &str) -> Query`: take the text after the first `?` (or nothing) and upper-case it (`ToUpper()` before parsing, so `%61` decodes to a lower-case `a`). Split at `&`, then each part at its first `=`; a part without `=` is ignored (null key in C#). `+` becomes a space, then `%XX` is decoded (`HttpUtility.UrlDecode`: invalid escapes literal, lossy UTF-8).
    - `get(&self, key: &str) -> Option<String>`: an exact upper-case key; several values are joined with `,` (`NameValueCollection.Get`).
  - `pub fn parse_float(s: &str) -> Option<f64>` (`double.TryParse(s, NumberStyles.Float, Invariant)`, .NET Framework): accepts surrounding white space, a sign, digits with an optional `.` fraction (at least one digit) and an optional exponent. Rejects thousands separators, `NAN` and `INFINITY` (the query is upper-cased, and net472 matches `NaN` case-sensitively).
